# User Feedback Log

这个文档专门收集 Netlify 上线后的真实用户反馈。这里优先保留用户原话，再做轻量分类，避免一开始就把反馈改写成我们自己的理解。

当前状态：第一批反馈已录入。代码已回退到较早状态，需要按 `v2-update-backlog.md` 重新逐项实现并 commit。

## 标签

- `题目质量`：例题、通关题、题干、选项、解析是否重复或泄露答案。
- `阅读体验`：正文、解析、颜色、对比度、字号、行高是否易读。
- `移动端`：手机、微信/小红书内置浏览器、窄屏布局体验。
- `练习反馈`：答题节奏、正反馈、错题解析、刷题体验。
- `关卡路径`：从首页到关卡、通关后返回/继续、进度按钮。
- `入口测评`：开场诊断、薄弱点推荐、从 0 开始入口。
- `内容精简`：术语、概念解释、关卡末尾内容是否过多。

## 第一批反馈

### FB-001

- 标签：`题目质量`
- 严重程度：P1
- 影响位置：多关卡例句 / 常见坑 / 通关练习
- 用户原话：
  > 有些关卡的例题和通关题是重复的，这一定要避免。
- 初步理解：
  - 例题负责教方法，通关题负责迁移检测，二者不能直接复用。
  - 需要全站扫描完全重复、句子重复但问法不同、结构高度相似的问题。
- 对应任务：V2-004

### FB-002

- 标签：`阅读体验`
- 严重程度：P1
- 影响位置：例句拆解 / 常见坑 / 练习解析
- 用户原话：
  > p1 图片中，白底灰字的 ui 设计十分差劲，不宜阅读。
- 后续补充：
  > 还是白底灰字啊，没啥区别。
- 初步理解：
  - 浅灰正文和浅底色组合导致重点不清，尤其手机端更难读。
  - 需要提高正文色、卡片背景、分块边框和行高。
- 对应任务：V2-005

### FB-003

- 标签：`移动端`
- 严重程度：P1
- 影响位置：全站
- 用户原话：
  > 我们目前制作的所有 ui 都是针对于电脑端，对于手机端的 ui，如果用户用手机打开我们的网址，很多 ui 的排布都很不理想。
- 初步理解：
  - 需要响应式布局，重点检查 375px、390px、430px、768px 和桌面。
  - 不一定需要强行检测设备，优先用 CSS media query 适配不同宽度。
- 对应任务：V2-006

### FB-004

- 标签：`练习反馈`
- 严重程度：P1
- 影响位置：每关过关练习
- 用户原话：
  > 我希望优化我们的通过每关的通过刷题板块，之前是通过滚轮从上往下做题，我现在希望是做一道题翻一道页，然后加强学生做对题的快感和反馈。
- 后续补充：
  > 每次答完题目以后都要点击下一题，这个操作感觉很麻烦。
  > 答对了就直接跳到下一题好了。
  > 做对了的弹窗多停留一秒吧，太快了用户看不清就没了。
- 初步理解：
  - 练习应每次聚焦一道题。
  - 答对后应短暂确认并自动进入下一题。
  - 下一题顶部保留轻量正反馈，例如 `答对 +1`、连对提示。
  - 答错仍应停留当前题，展开解析，由学生确认后继续。
- 对应任务：V2-007

### FB-005

- 标签：`内容精简`
- 严重程度：P2
- 影响位置：每关末尾概念名词解释 / 术语卡
- 用户原话：
  > 每一关最后的概念名词解释有点太多了，应该适当精简。
- 初步理解：
  - 每关末尾不应出现长串术语解释。
  - 保留最影响做题的 3-4 个术语即可。
- 对应任务：V2-008

### FB-006

- 标签：`关卡路径`
- 严重程度：P1
- 影响位置：每关通关完成区
- 用户原话：
  > 每一关完成之后的返回按键一定要放在最后，不然还要翻到最上面才能返回。
- 初步理解：
  - 通关完成区底部必须提供返回地图。
  - Level 1-9 可同时提供继续下一关；Level 10 只返回地图。
- 对应任务：V2-009

### FB-007

- 标签：`入口测评`
- 严重程度：P2
- 影响位置：首页 / 解锁策略 / 个性化推荐
- 用户原话：
  > 我建议我们在网站一上来，先放个简单的测试评估一下水平，然后找到用户的薄弱点，解锁对应关卡让他训练，当然用户也可以选择“我是语法小白，想从0开始”。
- 初步理解：
  - 需要设计诊断测评入口。
  - 推荐结果应影响首页主按钮和关卡解锁。
  - 这项需要单独讨论设计，不宜仓促实现。
- 对应任务：V2-010

### FB-008

- 标签：`关卡路径`
- 严重程度：P1
- 影响位置：首页路线选择区
- 用户原话：
  > 第二个 bug 就是这个右上角的开始第几关不更新。
- 初步理解：
  - 首页主按钮不应永远显示“开始第 1 关”。
  - 应根据已解锁/已完成进度显示“继续第 X 关”或“查看总复盘”。
- 对应任务：V2-011

## 待继续收集

## 第二批反馈

### FB-009

- 标签：`练习反馈`
- 严重程度：P2
- 影响位置：每关过关练习
- 用户原话：
  > 我们再来优化一下刷题反馈吧
- 讨论结论：
  - 先做轻量但明显的版本，不引入声音或复杂成就系统。
  - 答对瞬间给当前题卡更强的正反馈。
  - 答对后自动跳转延迟略增加，让学生看得清反馈。
  - 增加连对提示，强化连续做对的快感。
  - 增加练习进度条，提升完成感。
  - 答错仍停留当前题，展示解析，由学生确认后继续。
- 对应任务：V2-012

### FB-010

- 标签：`题目质量`
- 严重程度：P1
- 影响位置：Level 1-10 例句 / 常见坑 / 通关练习
- 用户原话：
  > 全面检查下我们网站的例句和题目质量有没有问题，有没有出现例句和题目重复的情况，然后适当提升质量
- 初步理解：
  - 不能只检查“同一关例题和通关题重复”，还要检查全站范围里例句、常见坑、通关题是否直接复用。
  - 高相似结构也需要纳入风险，例如同一关教学例句和通关题只替换一两个词。
  - 换题时必须同步更新选项、骨架、解析和标色片段，避免页面上句子换了但讲解还是旧句子。
- 对应任务：V2-013

### FB-011

- 标签：`阅读体验`
- 严重程度：P1
- 影响位置：全站 UI，重点是关卡学习正文、步骤卡、例句、常见坑、练习解析
- 用户原话：
  > 全面美化我们的ui，杜绝这种白底灰字看不清的情况
- 初步理解：
  - 不能只修某一张卡片，要统一学习区的正文色、辅助文字色、卡片底色和边框层级。
  - 主要学习内容不应再使用低对比灰字；辅助文字也要足够深。
  - 步骤卡、例句卡、常见坑卡、练习解析需要从“白底细边框”升级为更明确的学习卡片。
- 对应任务：V2-014

### FB-012

- 标签：`练习反馈`
- 严重程度：P1
- 影响位置：错因汇总 / 补救练习
- 用户原话：
  > 这里的补救我希望他们点击p2的补救按钮时，可以直接下滑到下方的题目
- 初步理解：
  - 用户点错因汇总里的补救按钮后，不应该还要自己往下找补救题。
  - 激活补救项后，页面应自动滚动到对应的补救练习面板。
  - 补救面板需要稳定的锚点和可访问名称，方便测试和后续定位。
- 对应任务：V2-015
